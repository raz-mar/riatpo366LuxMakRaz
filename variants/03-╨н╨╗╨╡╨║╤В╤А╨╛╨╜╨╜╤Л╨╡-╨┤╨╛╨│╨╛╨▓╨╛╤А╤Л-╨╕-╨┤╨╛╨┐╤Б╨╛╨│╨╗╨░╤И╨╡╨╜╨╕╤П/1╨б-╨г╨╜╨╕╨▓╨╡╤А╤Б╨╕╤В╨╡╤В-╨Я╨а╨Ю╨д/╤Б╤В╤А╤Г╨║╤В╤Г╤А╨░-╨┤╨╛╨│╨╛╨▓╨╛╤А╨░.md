# Структура договора в 1С:Университет ПРОФ

**Источник для аналитиков:** объектный состав, с которым договорной отдел уже работает.  
**Раздел интерфейса:** Финансы → Договоры на оказание образовательных услуг.  
**Статья по созданию объекта:** см. [`link.md`](../link.md).

Ниже — не «новая база», а поля существующего учёта. Электронное подписание **дописывается в этот же объект**, а не живёт отдельно.

## Объекты конфигурации

| Объект | Тип | Назначение |
|--------|-----|------------|
| `Справочник.ДоговорыНаОказаниеОбразовательныхУслуг` | справочник | основной договор с обучающимся |
| `Справочник.ДополнительныеСоглашенияКДоговорамОбучения` | справочник | доп. соглашение; ссылка на родительский договор |
| `Перечисление.СостоянияДоговоровОбучения` | перечисление | `Проект`, `Утвержден`, `Аннулирован` |
| `Перечисление.СостоянияЭлектронногоПодписания` | перечисление | контур ЕПГУ / «Госключ» (см. ниже) |
| `Справочник.ВидыДоговоровНаОбучение` | справочник | вид договора |
| `Справочник.ТипыПлатежаПоДоговорамОбучения` | справочник | шаблон графика: сроки и проценты |
| `Документ.ОплатаПоДоговорам` | документ | факт оплаты по строке графика (создаётся при утверждении, **вне рамок этого кейса**) |

После записи у договора автоматически заполняются `Код` и `Номер`. После команды «Утвердить договор» состояние с `Проект` меняется на `Утвержден`; в меню «Действия» появляются «Аннулировать», «Вернуть в состояние проекта», «Создать дополнительное соглашение».

## `Справочник.ДоговорыНаОказаниеОбразовательныхУслуг`

### Шапка — обязательные для создания

| Реквизит | Тип | Откуда берётся | Комментарий |
|----------|-----|----------------|-------------|
| `Обучающийся` | `СправочникСсылка.ФизическиеЛица` / карточка обучающегося | выбор | обязательный |
| `ИсточникФинансирования` | контрагент **или** физическое лицо | выбор | плательщик; может не совпадать с обучающимся |
| `ВидДоговора` | `СправочникСсылка.ВидыДоговоровНаОбучение` | выбор | обязательный |
| `УчебныйПлан` | `СправочникСсылка.УчебныеПланы` | выбор | обязательный; тянет даты и стоимость |

### Шапка — заполняется автоматически при создании

| Реквизит | Тип | Правило |
|----------|-----|---------|
| `ДатаДоговора` | дата | текущая дата |
| `Наименование` | строка | формируется из номера, обучающегося и вида |
| `ТипПлатежа` | ссылка на тип платежа | из настроек вида договора |
| `РасчетСуммыОплаты` | значение перечисления / способ расчёта | из настроек |

### Шапка — заполняется из учебного плана

| Реквизит | Тип | Правило |
|----------|-----|---------|
| `ДатаНачала` | дата | из учебного плана; при переводе / восстановлении — дата, с которой обучающийся переведён или восстановлен |
| `ДатаОкончания` | дата | из учебного плана |
| `СтоимостьОбучения` | число | из документа «Стоимость обучения» по выбранному плану |

### Шапка — идентификация после записи

| Реквизит | Тип | Правило |
|----------|-----|---------|
| `Код` | строка | системный код элемента |
| `Номер` | строка | по занятым номерам; последний номер можно поправить вручную |
| `Состояние` | `ПеречислениеСсылка.СостоянияДоговоровОбучения` | `Проект` → `Утвержден` → `Аннулирован` |

### Реквизиты сторон и обучения (для печатной формы)

Подставляются в макет, в карточке часто читаются по ссылкам, а не вводятся заново.

| Реквизит / путь | Содержание |
|-----------------|------------|
| Организация университета | полное и сокращённое наименование, ИНН, КПП, ОГРН, адрес, расчётный счёт, ФИО и должность подписанта |
| Обучающийся | ФИО, дата рождения, паспорт, адрес, СНИЛС, контакты |
| Плательщик | если это не сам обучающийся: ФИО / наименование, реквизиты, основание (законный представитель и т. п.) |
| Образовательная программа | специальность / направление, форма обучения, уровень, факультет, срок |
| Предмет договора | формулировка платных образовательных услуг по выбранному плану |

### Табличная часть `ГрафикПлатежей`

Перезаполняется при изменении учебного плана, даты начала или стоимости. Даты строк берутся из настроек типа платежа (год в шаблоне типа платежа значения не имеет). Строки можно править вручную; кнопка «Заполнить» возвращает график по умолчанию.

| Колонка | Тип |
|---------|-----|
| `НомерСтроки` | число |
| `СрокОплаты` | дата |
| `Процент` | число |
| `Сумма` | число |
| `Комментарий` | строка |

### Реквизиты электронного контура (дописываются к тому же объекту)

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| `СостояниеЭП` | перечисление | см. статусы ниже |
| `ДатаПодписиУниверситета` | дата/время | факт подписи вуза |
| `ДатаОтправкиНаЕПГУ` | дата/время | когда ушло второй стороне |
| `ИдентификаторЗаявленияЕПГУ` | строка | `orderId` из API ЕПГУ |
| `СНИЛСПодписантаСтудента` | строка | получатель в «Госключ» |
| `ОИДЕСИАПодписанта` | строка | альтернатива СНИЛС |
| `ДатаПодписиСтудента` | дата/время | когда вторая сторона подписала |
| `ФайлПечатнойФормы` | хранилище / присоединенный файл | PDF, который ушёл на подпись |
| `ПодписьУниверситета` | хранилище | отсоединённый PKCS#7 (`.sig`) |
| `ПодписьСтудента` | хранилище | файл подписи второй стороны |
| `КомментарийЕПГУ` | строка | ошибка / статус с портала |

`СостояниеЭП`: `НеОтправлялся` → `ПодписанУниверситетом` → `ОтправленСтуденту` → `ПодписанСторонами` / `ОтклоненСтудентом` / `ИстекСрокПодписания`.

## `Справочник.ДополнительныеСоглашенияКДоговорамОбучения`

Создаётся из утверждённого договора командой «Создать дополнительное соглашение». Печать и отправка на ЕПГУ — **тот же контур**, что у договора.

| Реквизит | Тип | Комментарий |
|----------|-----|-------------|
| `ОсновнойДоговор` | ссылка на договор | обязательный |
| `Номер` | строка | после записи |
| `Дата` | дата | |
| `ВидИзменения` | перечисление | стоимость, сроки, плательщик, программа, прочее |
| `Основание` | строка | формулировка для шаблона |
| `НоваяСтоимостьОбучения` | число | если меняется стоимость |
| `НоваяДатаНачала` | дата | |
| `НоваяДатаОкончания` | дата | |
| `НовыйУчебныйПлан` | ссылка | |
| `НовыйИсточникФинансирования` | ссылка | |
| `Состояние` | то же, что у договора | проект / утверждён / аннулирован |
| реквизиты ЭП | как у договора | те же поля электронного контура |

Табличная часть `ГрафикПлатежей` — по той же схеме, если доп. соглашение меняет оплату.

## Что человек больше не должен вводить

Если в 1С уже есть обучающийся, план, стоимость, стороны и график — карточка договора заполняется из них. Ручное действие остаётся только там, где нужно решение: утвердить, поправить исключение в графике, нажать **«Подписать и отправить студенту»**.
